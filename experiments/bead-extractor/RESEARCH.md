# 逆向拼豆导出图：方案调研与实验记录

## 结论

没有找到能够直接把“低分辨率、含网格和格内色号文字的拼豆导出图”还原为
工程矩阵的成熟开源项目。现有拼豆和十字绣软件几乎都是正向流程：缩小图片、
量化到线材或拼豆色板，再绘制网格和符号。它们的色板量化可以复用，但没有解决
本项目的逆问题。

最接近的公开方案来自三类工作：棋盘图识别、图表网格去除、重复可见水印分离。
对当前样图最合理的模型不是继续调整单格取色窗口，而是先分离可观测的几何证据，
再对颜色做图像内校准：

```text
观测格子 = MARD 离散底色 + 每条线宽度可变的网格层
          + 与颜色类别相关但不需要识字的字符纹理层 + 压缩/缩放误差
```

字符只作为无语义的干扰纹理；算法不读取、转写或匹配文字内容。粗线间隔不是算法
参数：每条线均独立测宽，粗细线可以按任意规律出现。

## 已实现的新流程

本轮实现不再用 Hough/RANSAC 候选线直接决定网格。RANSAC 只有在真网格候选已经
占优势时才能排除随机离群点；成排字符和人物轮廓同样可能形成稳定的平行结构，并不
满足“随机离群”的前提。

当前流程采用“周期提议 -> 连续性投影 -> 正交梳外框 -> 多卡尺逐线测量”：

- 自相关只提议一格周期，并等价考察所有整数谐波，不给第 5、6、7 或第 10 条线任何
  特权。
- 低分位投影要求证据沿线持续出现，人物局部轮廓和单个字符因此难以控制全局相位。
- 横线集合用于验证纵向范围，纵线集合用于验证横向范围，避免标题和底部色表扩大
  画布。
- 每条线用多个互相独立的卡尺截面测中心和有效宽度；相邻的双梯度峰与已经分离的
  左右梯度峰使用同一个“完整污染支撑区”定义，避免粗线只量到其中一侧。中心由近似
  等距模型约束，宽度完全独立，弱线可插值但会记录置信度和警告。
- 下游严格按逐线宽度和 halo 建污染掩码，格子中心没有特殊地位。
- 工程 JSON 的可选 `sourceGrid` 保留逐条线宽；诊断渲染按目标尺寸分别缩放这些
  宽度，不再把所有网格线硬编码成 1px。旧工程没有该字段时仍兼容 1px 回退。
- 能识别的双亮度棋盘背景输出为 `null`；可靠等宽色表只通过色块顺序匹配 MARD，
  不读取色号。实测色块原型再由同图格子样本做有限次稳健更新。

流程不存在按阶段短路的“严格模式”。只要仍有可计算的网格，后续空格、颜色、模板和
诊断都会运行；尺寸越界、插值线过多和颜色歧义统一进入最终警告。

## 公开项目与研究

### Cstitch

[Cstitch](https://github.com/kleintom/Cstitch) 是开源十字绣图案生成器。它证明了
“输入图片 -> 色板量化 -> 网格/符号导出”的正向流程已有成熟实现，但没有从带符号
网格图恢复原始颜色矩阵的模块。

### img2sgf

[img2sgf](https://github.com/hanysz/img2sgf) 从围棋棋盘图片生成 SGF。其重要经验是：

- 先检测并临时移除棋子，否则成排棋子会产生假直线；
- 再做 Canny/Hough 直线检测；
- 对直线截距聚类，用等间距补全漏线；
- 聚类过多或间距不可信时拒绝结果，而不是强行切分。

这与当前问题直接对应：格内字符和图案轮廓会形成大量假峰，所以 Hough、RANSAC
或逐线吸附不能单独保证网格正确。RANSAC 只能在“真网格线已经是优势模型”时排除
离群线；当重复字符本身形成稳定平行线时，它们不是随机离群点，RANSAC 也可能拟合
到错误模型。

### WebPlotDigitizer

[WebPlotDigitizer](https://github.com/automeris-io/WebPlotDigitizer) 的早期网格去除实现
按选定网格色阈值化，然后统计每一行、每一列的命中比例；比例超过阈值就把整条轴
标记成网格。相关版本保存在
[Zenodo 3.9 记录](https://zenodo.org/records/32375)。

这种“颜色证据 + 轴向占用率”很适合生成网格掩码，也启发了本项目的整行/整列泄漏
检测；但它用一个全局背景色覆盖网格，只适合从白底图表提取曲线，不能恢复网格下面
属于不同格子的彩色底色。

### 多图可见水印分离

Dekel 等人的 CVPR 2017 论文
[On the Effectiveness of Visible Watermarks](https://watermark-cvpr17.github.io/)
把多张带同一水印的图片放入联合 alpha 合成模型，交替估计水印前景、透明度和干净
背景。这是与当前问题最接近的研究：200x200 图提供了 40,000 个重复格子样本，
共享网格相当于重复水印。

原论文模型可概括为：

```text
J_k = c_k * alpha * W + (1 - c_k * alpha) * I_k
```

当前任务还多一个关键结构：字符纹理随 MARD 类别变化，因此不能只拟合一个全局
覆盖层，需要“共享网格模板 + 类别相关字符模板”的混合模型。

[Double-DIP](https://arxiv.org/abs/1812.00467) 也能在没有外部训练集的情况下做单图
层分解；但它使用未训练神经网络先验，计算昂贵、存在随机性和幻觉风险，不符合本项目
对纯图像处理和稳定可复现的优先级，因此不作为主方案。

### RPCA 与非局部方法

[Robust PCA/PCP](https://arxiv.org/abs/0912.3599) 将观测矩阵分成低秩项和稀疏项；
[Non-local Means](https://doi.org/10.5201/ipol.2011.bcm_nlm) 通过全图相似块平均来降噪。
两者都能作为联合模型的正则项，但不能直接完成本任务：共享网格在所有格子中出现，
并不是跨样本稀疏项；66 种底色和类别相关字符也会提高矩阵秩。普通 RPCA/NLM 会把
少量出现的一格细节当噪声抹掉。

## `hutao.JPG` 对照实验

所有预览位于 `output/research/`。这些实验没有工程真值，只能比较可观测的条带冲突、
用色数和视觉结果，不能据此宣称颜色准确率。

| 路线 | 结果 | 判定 |

| 全局共享 alpha 覆盖层 | 逆变换放大低透射区域，仍有整行条带 | 淘汰 |
| 100 个粗网格相位的仿射覆盖层 | 108 色，Delta E 中位数 2.17，条带仍明显 | 淘汰 |
| 底部色表的 66 个实测原型 + 单格截尾一致性 | 只用 61 个原型；普通结果仍有大量条带 | 原型约束有效，单格判别不足 |
| 上述结果的无条件局部共识 | 条带冲突从 4046/3994 降到 553/481，但修改 6467 格并吞掉细节 | 过度平滑，淘汰 |
| 非局部类别模板 EM | 错误初值中的条带被学习为类别纹理并自我强化 | 淘汰 |
| alpha 合成轨迹似然 | 视觉较干净，但只剩 53 类，多个真实红/棕色被合并 | 不能用降色数隐藏错误，淘汰 |
| Viterbi 联合选择 201 条网格边界 | 格宽受限后仍会整段选错相位；95 色且横线明显 | 淘汰 |

## `xiadie.JPG` 对照

该图是另一种导出样式：逻辑画布为 `93x81`，空格显示为透明棋盘纹理，单格约
15 像素。界面给出的人工核对信息为 23 色、4929 颗；程序不读取这些文字，它们只
用于评价实验结果。

旧流程曾错误检测为 `90x73`，范围为 `x=0..1338`、`y=279..1367`：顶部约 11 行
被遗漏，左侧坐标栏被纳入画布，底部图例又被当作网格内容。这说明仅依赖内部周期，
缺少完整外框、四边一致性和末端行列验证时，置信度并不可信。

第一次人工几何对照使用了未经像素测量的目测边界
`left=28, top=110, right=1423, bottom=1325`。该边界是错误的：横向多纳入约
10.8 像素，纵向多纳入约 8.6 像素，误差沿 93 列和 81 行累积，右下区域接近错开
大半格。该组预览和统计不再作为有效实验结果。

新流程不使用粗线间隔，自动测得边界约为 `left=27.20, top=110.55` 至
`right=1411.90, bottom=1316.58`，格距约 14.89 像素，逻辑尺寸为 `93x81`。结果如下：

- 主体中的网格泄漏明显少于 `hutao.JPG`，说明单格分辨率提高后，现有颜色密度簇
  能恢复大部分主体结构。
- 自动检测 23 个等宽图例色；颜色集合与可见图例一致。
- 棋盘背景输出 2,606 个 `null`，得到 4,927 颗；可见人工统计为 4,929 颗，仍有
  2 格偏差。程序不读取该统计，它只用于评价。
- 23 个非空颜色中有 13 格低置信度；15 条弱横线由等中心格模型插值并产生警告。

因此该图确认了两个必要环节：完整逻辑外框不能等同于最大周期纹理区；MARD 分类前
必须有独立的透明棋盘/空格类别，且不能把某个固定浅色 RGB 简单规定为空。

## 仍未解决的问题

### 空格策略的实验隔离

棋盘混合模型已经冻结为 `checker-mixture-v1`，由 CLI 的 `--empty-strategy baseline`
进入，任何后分类规则都不得修改这一路径。新的空格/活动色联合判断放在独立的
`empty_strategies.py` 中，通过 `conflict-aware` 显式启用。`compare` 模式会对同一
输入分别执行两条路径，并保存逐格差异，避免用总颗数相同掩盖“误删和误加互相抵消”。

当前 `conflict-aware` 仍是待验证实验，不因某张图片的可见总数吻合而升级为基线。
邻域关系可以作为诊断证据，但在没有一格宽细节和内部透明孔洞真值之前，不应默认为
最终分类依据。

`hutao.JPG` 的单格只有约 7.135 像素。逐线掩码解决了“边界像素被当成格子颜色”，
但格内剩余像素仍被模糊色号覆盖。底部图例又是变宽紧凑排版，不满足当前等宽色表
模型；候选解释的中位色差约为 16，故程序禁用它并保留完整色板分类。当前仍预测
98 色、2,688 个低置信度格，浅色区域可见条带，不能宣称已经准确恢复。

后续应优先验证以下两条确定性路线，而不是无条件空间平滑：

1. 对变宽图例检测独立色块连通域，按几何顺序与色板做缺失/多余均可容忍的动态规划
   匹配；只有颜色残差和布局残差同时低时才限制活动色集合。
2. 在有原始 JSON 真值的数据上验证“图像内颜色群体原型”或离散 MRF。目标必须同时
   约束像素重建误差和边界保留，尤其检查真实的一格宽线条，避免把少色和平滑误当
   准确。

最关键的验证数据仍是“原始工程 JSON + 同一工程导出 JPG/PNG”。至少需要覆盖浅色、
深色、相近色、小面积单格线条和不同画布尺寸。没有这些真值，视觉更平滑不能等同于
恢复更准确。
